# 7 种核心布局模式

每种模式都有对应的 SVG 模板（在 `templates/` 下）和明确的适用场景。**画图前先想清楚用哪种模式，不要混用。**

---

## 1. 三层架构（Three-Layer Architecture）

### 适用场景
- 表达多层级体系的整体观
- 各层之间有明确的"职责分工 + 数据流"关系
- 典型：协议栈、监控分层、组织架构

### 视觉特征
- 三个等高横向色块自上而下排列
- 每层左侧是色块+图标，右侧是文字说明
- 层与层之间有箭头表示数据流向（双向或单向）

### 关键设计
- **每层的左侧色块颜色就是语义编码**（红/紫/绿）
- 每层文字内含：标题 + 触发反应 + 判定方式 + 例子
- 层间箭头**必须**标注流向语义（"触发依据""数据来源""数据沉淀"）

### 模板
`templates/three-layer.svg`

### 案例
监控指标 V3 图解的"图 01 总体三层架构"

## 2. 决策树（Decision Tree, 主干+旁路）

### 适用场景
- 表达"给定输入 X，怎么决定它的归类/处理方式"
- 有 2-5 个判断节点，最终走向 3-5 个结果
- 典型：候选指标归类、错误处理路径、用户分流

### 视觉特征
- **中央粗黑主干线**从顶部"输入"一路向下到底部"主要结果"
- 每个判断节点是一个圆角矩形（不用菱形——菱形挤）
- 非主干分支**向左/右伸出**到旁路出口

### 关键设计
- 主干上的判断节点用白底黑框，旁路出口用纯色块（红/紫/绿/灰）
- yes/no 的标签写在线条旁边，不写在判断节点里
- 子分支（如 Q2a 同源 judge 判断）用**虚线框包起来**作为一个独立小子树
- 配套机制（如"心电图作为底座"）用底部独立的紫色虚线框单独说明，**不要塞进决策树**

### 模板
`templates/decision-tree.svg`

### 案例
监控指标 V3 图解的"图 02 候选指标的归类流程"

## 3. 故事卡网格（Story Cards Grid）

### 适用场景
- N 个并列概念（5-12 个），每个需要展示故事 + 应对
- 典型：N 种错误模式、N 个工具、N 个角色

### 视觉特征
- 3×N 或 4×N 网格布局
- 每张卡片含：编号圆 + 标题 + 📝 故事 + 🔍 监控/应对 + 底部徽章
- 卡片底部 + 整体下方有"覆盖映射汇总区"

### 关键设计
- **编号圆使用语义色**（红圆 = 急诊类卡片）
- 徽章放在**底部右侧**（不要放右上角，会挡标题）
- 卡片高度统一（即使内容长度不同，也要保持统一高度）
- 卡片用 foreignObject 嵌入 HTML 文字，便于自动换行

### 模板
`templates/story-cards.svg`

### 案例
监控指标 V3 图解的"图 03 急诊 9 大警报故事卡"

## 4. 心电图 / 生命周期追踪（Lifecycle Trace）

### 适用场景
- 表达"某个实体在时间维度上的状态变化"
- 有明确的事件类型清单 + 一个具体案例追踪
- 典型：约束追踪、订单生命周期、用户漏斗

### 视觉特征
- 左右两栏：左侧是"事件类型清单"，右侧是"具体案例的事件序列"
- 案例追踪用纵向时间线（圆点 + 连线）
- 底部是"洞察盒子"（黄色）+ 衍生指标卡

### 关键设计
- 事件类型用紫色色块（左侧色条 + 标题 + 说明）
- 案例追踪的圆点用绿色（正常）和红色（异常）区分
- 死亡点（首次异常）用红色虚线连接 + "死亡点！"标注
- 配 1 个 JSON 样例 + 1 个"如果没有这个机制会怎样"对比

### 模板
`templates/lifecycle-trace.svg`

### 案例

## 5. 多组分类仪表盘（Multi-Group Dashboard）

### 适用场景
- N 个并列分组（4-6 组），每组下面有若干指标/条目
- 各组之间地位平等，仅按主题区分
- 典型：监控仪表盘分组、产品功能分组

### 视觉特征
- 每组一个大卡片（占半行或全行）
- 卡片顶部是色彩 header（组名 + 数量徽章）
- 卡片内部：指标列表 + 💡 用途 + 📈 示例

### 关键设计
- **每组结构必须完全一致**（💡 用途、📈 示例每组都有，缺一不可）
- 如果某组特别重要（如元监控），可以单独占一整行而不是半行
- 组色按语义分配（蓝=流程，紫=决策，黄=工具，绿=成本，红=元监控）
- ⚠️ 这是踩过坑的地方：**SVG `<text>` 里不能用 `<u>` 等 HTML 标签**，会破坏后续组的渲染

### 模板
`templates/group-dashboard.svg`

### 案例
监控指标 V3 图解的"图 05 体检仪表盘 5 组分类"

## 6. 阶段甘特图（Phased Rollout）

### 适用场景
- 表达分阶段实施的时间线
- 重点是"做不做"，不是"做多久"
- 典型：实施梯队、产品 roadmap

### 视觉特征
- 横向三列（或四列）等宽，对应"阶段一/二/三"
- 每行一个条目，色块出现在它所属的阶段那一列
- 行末徽章标注覆盖的目标 / 问题 / KPI

### 关键设计
- **不要用具体周数**（"第 1 周""第 2 周"）—— 用"阶段一""阶段二"
- 阶段标题用大色块（红/黄/绿渐进）
- 色块颜色按层级（红=急诊、紫=心电图、蓝=仪表盘）
- 阶段之间用虚线分隔，明确边界

### 模板
`templates/phased-rollout.svg`

### 案例
监控指标 V3 图解的"图 06 实施阶段"

## 7. 执行点锚定（Pipeline Anchor）

### 适用场景
- 把抽象的方案"钉"到具体系统的执行点上
- 表达"在哪里触发什么"
- 典型：埋点分布、规则触发点、监控位置

### 视觉特征
- 上半部分：主干流程（垂直列出主要 stage / 节点）
- 下半部分：横切触发点（垂直列出"每次 X 时" + 触发的指标 pill）
- 每行：左侧黑色 trigger 标签 → 右侧色彩 pill 列表

### 关键设计
- **主干 + 横切**两段式（这是最关键的结构创新）
- 主干每行：stage 编号方块 + 箭头 + 触发的 pill 列表
- 没有 stage 特有指标的 stage，用灰色虚线框标注"仅触发横切指标"
- 横切部分用黑色 trigger 标签作为锚点（"每次 Task() dispatch""每次 Skill() call"）
- pill 颜色严格按语义色

### 模板
`templates/pipeline-anchor.svg`

### 案例
监控指标 V3 图解的"图 07 指标钉在 pipeline 的哪些执行点上"

## 选型决策表

| 你想表达 | 用哪种模式 |
|---|---|
| 整体有几层、各层做什么 | 1. 三层架构 |
| 输入 X 怎么分流 | 2. 决策树 |
| N 个并列概念逐个解释 | 3. 故事卡 |
| 某个实体在时间上的变化 | 4. 心电图 |
| N 个并列分组 + 每组多个条目 | 5. 仪表盘 |
| 分阶段做什么 | 6. 阶段甘特 |
| 抽象方案怎么落地到代码点 | 7. 执行点锚定 |

如果一个需求**同时涉及多个**，拆成多张图分别表达，不要混用。
