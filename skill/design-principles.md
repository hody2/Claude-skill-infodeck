# Design Principles

5 条贯穿整个 skill 的设计原则。生成任何图示前都必须读一遍。

---

## 原则一：每张图回答一个具体问题

**❌ 反例**：一张图叫"系统架构"，画了 20 个框 + 50 根线。读者不知道你想让 ta 看什么。

**✅ 正例**：图标题是"如果一个候选指标 X 出现了，它该归到哪一类？"。读者打开图就知道这张图的用途。

**操作落地**：
- 每张图都先写"这张图回答什么问题"（写在 `<div class="lead">` 里）
- 如果一张图能回答 3 个以上问题，把它拆成 2-3 张
- 标题用陈述句或问句，不要用名词短语（"系统架构" → "系统的三层架构和数据流向"）

---

## 原则二：颜色编码全篇统一

**核心规则**：在第一张图就建立颜色编码，之后每张图都遵守。

**典型映射**：
- 红色 = 紧急 / 阻塞 / A 类 / 第一层
- 紫色 = 中间层 / 数据底座 / B 类 / 第二层
- 蓝色 / 绿色 = 趋势 / 非阻塞 / C 类 / 第三层
- 灰色 = 丢弃 / 不重要 / 待处理

**❌ 反例**：第一张图用红色表示"急诊"，第三张图又用红色表示"P-01 问题徽章"。读者会困惑。

**✅ 正例**：始终用红色色块表示"急诊指标"，P-01 徽章也用红色但加白色文字 + 边框，视觉上区分但语义一致。

**操作落地**：在 `<style>` 里定义 CSS 变量（见 `color-system.md`），全篇引用。不允许在 SVG 里写裸的颜色值（如 `fill="red"`），必须用变量名。

---

## 原则三：信息密度高，但每张图都有"怎么读"入口

**核心规则**：每张图前面**必须**有一个黄色 `<div class="reading">` 提示框，告诉读者怎么看这张图。

**模板**：
```html
<div class="reading">
  <strong>左半边</strong>：xxx。<strong>右半边</strong>：xxx。<strong>箭头方向</strong>：xxx。<br>
  色块颜色：<span style="background:#c0392b;color:#fff;padding:1px 6px;">🚨 急诊</span> 等
</div>
```

`.reading` 的 CSS 会自动在前面加一个 "📖 怎么看这张图" 标题。

**为什么这条这么重要**：技术图示天然信息密度高，没有引导的话读者第一眼会被劝退。这个黄色框相当于"读图说明书"，把读图门槛从 30 秒降到 5 秒。

**❌ 反例**：直接画一个有 10 个节点 + 颜色编码 + 虚线/实线区分的复杂决策树，没有任何说明。读者要花 2 分钟才看懂。

**✅ 正例**：图前先有一段"中间粗线是主干，每个判断点的非主干分支向右伸出"，读者 10 秒就能进入图。

---

## 原则四：叙事顺序必须是"总体 → 决策框架 → 详细 → 关系映射"

**核心规则**：4-8 张图的排列顺序，必须符合人类理解新概念的认知节奏。

**典型节奏**：
1. **总体架构图**（让读者先建立全景）
2. **决策框架 / 分类流程**（让读者掌握判断逻辑）
3. **详细卡片或清单**（让读者填充细节）
4. **关系映射 / 触发点**（让读者看到怎么落地）
5. **实施时间线**（让读者知道下一步做什么）
6. **真实场景锚定**（让读者把抽象方案对应到他们熟悉的系统）

**为什么这个顺序**：
- 先架构再细节：避免读者"只见树木不见森林"
- 决策框架放第二张：让读者掌握后面所有取舍的依据
- 关系映射放后面：抽象关系需要先理解了实体才能消化

**❌ 反例**：第一张图就是"9 个急诊警报详细卡片"，读者还没建立全景就被信息淹没。

**✅ 正例**：第一张是三层架构，第二张是决策树，第三张才是 9 个详细卡片。

---

## 原则五：写完一定要"section count balance"检查

**核心规则**：HTML 文件写完后必须用 bash 工具跑一遍验证：

```bash
grep -c "<section" output.html  # N
grep -c "</section>" output.html  # 必须 = N

grep -c "<svg" output.html  # M
grep -c "</svg>" output.html  # 必须 = M

grep -n '<u>\|<b>\|<i>\|<strong>' output.html | grep -v "foreignObject"
# 必须为空（SVG <text> 里不能有 HTML 标签）
```

**为什么这条很重要**：实战中遇到过的 bug 是 B3 的 SVG 里写了一个 `<u>异构</u>`，导致整张图只渲染 B1/B2/B3，B4 和 B5 完全消失。**SVG 严格模式不允许 HTML 标签**，遇到就中止后续解析。

肉眼看代码看不出来——必须靠 grep 验证。

**操作落地**：每次生成完 HTML，先在 bash 里跑上面三个 check，再交付给用户。如果有问题，**主动修复**而不是让用户去发现。
