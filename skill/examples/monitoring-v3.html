01总体三层架构

把监控想象成一家医院——三个不同强度的"诊疗层"，各管不同的事
自上而下读：急诊（治急病）→ 心电图（追踪关键指标）→ 体检（看长期趋势）。中间的箭头表示数据流向——急诊触发依赖心电图，体检的数据底座也是心电图。
记忆要点：急诊 = 即时阻塞 + 规则判定；心电图 = 全程记录 + 不阻塞但是其他两层的数据底座；体检 = 长期趋势 + 不阻塞。原则贯穿三层："发现异常用规则，分析原因才用 AI"。

02候选指标的归类流程

当我们想加入一个新指标时，沿主干向下问 3 个问题，每个分叉指向不同归宿
中间粗线是主干，从顶部"候选指标"一路向下到底部"急诊警报"。每个判断节点都有一个分叉指向旁路出口（仪表盘 / 丢弃）。如果一路活到底，就是急诊警报。
用法示例："完成率" → Q1 有动作 → Q2 能用规则 → Q3 review 兜得住（review 不通过的项目本来就不会跑完）→ 进仪表盘。
"硬约束跨阶段传递" → Q1 有动作 → Q2 能用规则 → Q3 会静默通过（review 看不到字段消失）→ 进急诊，并配套心电图记录每一笔传递事件。

03第一层 · 急诊 9 大警报故事卡

每个警报对应一个真实发生过或可能发生的失败故事，按"如果不监控会发生什么"来记忆
9 个卡片按编号排列。卡片底部标注它直接覆盖哪个已知问题（P-01 ~ P-06）。
关键洞察：9 个警报全部用规则/schema/grep 实现，零 LLM 评判。第一阶段直接捕获 P-01、P-02、P-04、P-05 四个最严重问题；P-03 和 P-06 留给后续阶段。

04第二层 · 硬约束心电图详解

这是整个监控体系最有诊断价值的一层。用 Madrona 案例追踪它的完整工作机制
左半边：心电图的事件类型（一条约束在生命中会遇到的"体检点"）。右半边：用 Madrona 真实案例做追踪示范，可以看到约束在哪一步"心跳骤停"。底部：从这张心电图能产出的 4 个衍生指标。
类比记忆：急诊警报是"医生听到病人喊疼按下急救铃"；心电图是"24 小时 Holter 监护，事后能播放完整心律"。两者都重要——一个负责"立刻处置"，一个负责"长期诊断"。

05第三层 · 体检仪表盘 5 组分类

~20 个 trend 指标分 5 组管理，每组解决一类长期问题
每组用一种颜色，组名下方列出该组的所有指标。这一层都不阻塞 pipeline，只看趋势。
为什么 B5（元监控）单独占一行：这一组的存在解决了"监控自己挂了怎么办"的反模式。整套监控体系都依赖 review skill 工作良好，B5 就是给 review 体检的——以及给监控自己体检的。

06实施阶段 · 三个阶段的推进顺序

不是一次做完所有指标，而是按"覆盖问题数 / 实施难度"分三阶段推进
每行一个指标，色块出现在它所属的阶段那一列。红色 = 急诊警报、紫色 = 心电图、蓝色 = 仪表盘。每行末尾的徽章标注该指标直接覆盖哪个 P 问题。
关键节奏：阶段一完成所有"零 LLM 评判"的指标 + 心电图埋点（不一定立刻做统计）。这符合"采集端宁多勿少"——先把数据存下来，分析能力慢慢加。阶段二填齐跨系统/输出契约，阶段三做长期仪表盘和 P-06 根治。

07指标钉在 pipeline 的哪些执行点上

每个 stage、每次 Task() dispatch、每次 Skill() call、auto-improve 循环——都是触发点
上半部分是 主 pipeline 8 个 stage，每行展示该 stage 会"亮起"哪些指标。下半部分是 横切触发点，无论在哪个 stage 都会被触发的指标。
色块颜色：🚨 急诊 💓 心电图 📊 仪表盘
读法：上半部分（S1-S8）是"在哪个 stage 触发什么"；下半部分（横切）是"在哪类执行点触发什么"。S7 用黄色虚线框单独高亮，因为 auto-improve 循环是指标密度最高的区域——也是最容易出问题的区域。
